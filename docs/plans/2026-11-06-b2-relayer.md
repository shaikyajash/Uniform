# B2 Relayer Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A separate program, the Relayer, sends transactions for the Order Desk and pays their gas, so customers only sign. Done when the Relayer submits `DirectPay.pay` on Whitechain from a note a customer signed through the Order Desk.

**Architecture:**
- The Order Desk and the Relayer never call each other. They share one Postgres table, `relayer_jobs`. The Order Desk writes a job; the Relayer takes it, sends it and records the result. Either can be down while the other keeps working.
- A job holds typed arguments (`common::jobs::Job`), never raw calldata. The Relayer builds each call itself, so it can only send the few calls it knows. This is the drain protection the Whitechain Scale track asks about.
- `POST /v1/orders/{id}/direct` (Order Desk) takes `{quoteId, signature}`, recovers the signer from the stored note, writes a `direct_pay` job and moves the order `quoted -> paying`. One live job per order (a partial unique index).
- The Relayer loop: take one job with `FOR UPDATE SKIP LOCKED` and a random lease token (every later write checks the token, so a Relayer that lost the job writes nothing), check it, dry-run it, **sign it and save the signed bytes and hash**, then send them, wait for the receipt and record the gas. Every RPC call has a 10-second limit.
- The Relayer never marks an order paid. `paid` comes only from the `Paid` event on `/internal/events`.

**Checks before sending `DirectPay.pay` (docs/SPEC.md):**
- the note is unused: `USDT.authorizationState(payer, nonce)` is false;
- the payer holds the amount;
- Tether has not blocked the payer (`isBlocked`);
- the amount is at most `RELAYER_MAX_ORDER_USDT`;
- the merchant's gas spent today on this chain is under `RELAYER_DAILY_GAS_WEI`;
- `eth_call` of the exact transaction succeeds.

If a check or the dry run fails before anything is signed, the job is `failed` with the reason and the order goes back `paying -> quoted`, so the customer can sign again. Once a transaction was sent, the order goes back only when the note can no longer pay (it ran out unused), because until then a transaction carrying it could still be mined. `/quote` refuses an order that is `paying`; only the Relayer moves it back. Orders above `RELAYER_MAX_ORDER_USDT` are refused when the merchant creates them.

**Crash safety:** the signed transaction is saved before it is sent, so after a timeout or a crash the same bytes go out again: same nonce, same hash, never a second payment. A transaction not mined after 45 s is replaced with a 25% higher fee on the same nonce (at most 3 times), so only one of them can be mined. If the note was used by another transaction (an earlier one of ours, or anyone else's), the Relayer follows that one and never reopens the order. A note can never be paid twice: its nonce is single-use on chain.

**Out of scope:** Path B and C jobs (B4, B5), the claim job for `/secret` (B5), refund jobs (B7), one key per chain (one `RELAYER_PRIVATE_KEY` for now; only Whitechain is used in B2).

**Config:** `RELAYER_PRIVATE_KEY` (never printed or committed), `RELAYER_MAX_ORDER_USDT` (default 100), `RELAYER_DAILY_GAS_WEI` per merchant and chain (default 0.05 WBT), `DATABASE_URL`, `CHAINS_JSON`, and optional `SHOP_CHAIN_RPC` to point at a local anvil copy.

---

### Task 1: Job types in `common`

**Files:** `server/common/src/jobs.rs`. `Job::DirectPay {orderId, merchant, amount, payer, validAfter, validBefore, signature}` as JSON. Tests: JSON round trip, the signature is exactly 65 bytes.

### Task 2: Migration

**Files:** `server/order-desk/migrations/0002_relayer.sql`: `relayer_jobs` (status `pending -> sending -> sent -> confirmed | failed`, tx hash, attempts, last error, gas) and `gas_budget` (merchant, chain, day, spent). Tests: one live job per order; a status outside the list is rejected.

### Task 3: `POST /v1/orders/{id}/direct`

**Files:** `server/order-desk/src/routes/direct.rs`. Tests: a valid signature writes one job and moves the order to `paying`; a signature by someone else is `bad_signature`; an expired quote is `quote_expired`; a second submit is `already_submitted`; a 64-byte signature is rejected.

### Task 4: Relayer job loop against the database

**Files:** `server/relayer/src/{main.rs, jobs.rs}`. Tests: take one job at a time; a failed check fails the job and returns the order to `quoted`; the gas budget blocks a job.

### Task 5: Chain checks and send

**Files:** `server/relayer/src/chain.rs`. Dry runs against the real Whitechain (free): a note from a wallet with no USDT fails the balance check before any send.

### Task 6: Live check (spends gas)

Needs a funded `RELAYER_PRIVATE_KEY` and a payer with 1 USDT. One real `DirectPay.pay` on Whitechain, about 0.0009 WBT (measured on an anvil copy: 181,556 gas). Expected: the job is `confirmed` and `Paid` shows on the explorer.

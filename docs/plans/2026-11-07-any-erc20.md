# Any ERC-20, gas-free (EIP-7702 through Calibur)

Customers can pay with any ERC-20 we list (WETH, WBTC, ...), not only Circle's USDC and EURC, and
still pay no gas. Branch `any-erc20`.

Example: Riya has 0.001 WBTC on Ethereum Sepolia and no ETH. She picks WBTC and clicks Pay once.
Her Privy wallet silently signs (first time only) an EIP-7702 authorization to Calibur, and one
Calibur batch: approve WBTC to SourceLock, then lock it for Bob. Our Gas Payer submits it and pays
the gas. Bob values the lock at the live BTC price, fills on Whitechain, and later redeems the WBTC.

## Rule per token (`shared/chains.json`)

- Token with `eip712`: EIP-3009 signed note, unchanged (USDC, EURC, USDT).
- Token with `priceId` (CoinGecko id): Calibur batch, valued at market price. WETH on Base Sepolia
  and Ethereum Sepolia; WBTC on Ethereum Sepolia (Aave's faucet mints it).
- `contracts.calibur` on each customer chain: Uniswap's Calibur v1.1.0,
  `0x000000005c84F8Fd50b21CAC312528A64437030e` (audited by OpenZeppelin and Cantina; checked
  deployed on Base Sepolia and Ethereum Sepolia).

## Calibur batch (`server/common/src/calibur.rs`)

- Calls, in order: `token.approve(sourceLock, amount)`, `sourceLock.lock(params, token, amount)`.
  `revertOnFailure = true`, `keyHash = 0` (the wallet's own key), `executor = 0` (calls are fixed,
  so a front-runner only does the same lock).
- `nonce = nonce_for(lockId)`: its own Calibur nonce key, sequence 0. No chain read needed.
- `deadline`: unix seconds (the quote's note lifetime).
- EIP-712 domain: name `Calibur`, version `1.0.0`, chainId, `verifyingContract` = the customer's
  address, `salt` = Calibur's address as bytes32. `calibur::typed_data` gives the wallet JSON;
  `calibur::signing_hash` the digest (a test checks they match).
- Sent as a transaction to the customer's address: `execute(signedBatchedCall,
  abi.encode(signature, ""))`. With an EIP-7702 authorization (type `0x04`) when the wallet is not
  delegated to Calibur yet; its code then becomes `0xef0100 ‖ calibur`.

## Job

`Job::SourceLock` gains `batch: Option<calibur::Batch>` (`nonce`, `deadline`, optional
`authorization {chainId, address, nonce, yParity, r, s}`). Kind stays `source_lock`, so legs,
refunds and failure handling work unchanged. With `batch`, `signature` is over the Calibur batch
and `validAfter`/`validBefore` are 0.

## API (Order Desk)

- `POST /v1/orders/{id}/quote {payer, hashlock, chainId, token: "WBTC"}`. `token` defaults to
  `USDC`. For a priced token the reply's `toSign[0]` has `signing: "batch"`, `token` (symbol),
  `tokenAddress`, `decimals`, `amount` (token units, decimal text), `lockId`, `calibur`, and
  `typedData` (the Calibur batch). `total` is in that token.
- Amount: the order plus Bob's fee in USD, at the CoinGecko price, with a safety buffer, rounded
  up: `ceil(usd6 × 10^decimals × 10000 / (priceMicroUsd × (10000 − QUOTE_BUFFER_BPS)))`, with
  `QUOTE_BUFFER_BPS` above the Matchmaker's buffer, so a small price move still fills.
- `POST /v1/orders/{id}/legs {quoteId, signatures: [batchSignature], authorization?}`.
  `authorization` is what Privy's `useSign7702Authorization` returns, sent only when the wallet's
  code is not already `0xef0100 ‖ calibur`.

## SourceLock

Accepts any ERC-20 (the USDC/EURC note path is unchanged). `lock()` checks the contract received
exactly `amount` (no fee-on-transfer or rebasing tokens). Redeployed on Base Sepolia and Ethereum
Sepolia.

## Gas Payer

For a `source_lock` job with `batch`: rebuild the calls itself from the job (never from the
client), check the lock id, the token balance, the deadline, the wallet's code (empty, or
delegated to Calibur only), and that any authorization names Calibur on this chain; dry-run with
the authorization list; send. Done = SourceLock `locks(lockId).state != None`.

## Matchmaker

Values a lock of a priced token at its CoinGecko price less its buffer, in the token's own
decimals, the way it values EURC.

## Pay page

Shows WETH/WBTC balances per chain. On Pay with a priced token: quote with `token`, check the
wallet's code, sign the 7702 authorization if needed (silently), sign the batch (silently),
submit both.

## Not in this change

Refunds after a paid order are USDT on Whitechain, as for every payment. A lock that times out
returns the customer's own token.
